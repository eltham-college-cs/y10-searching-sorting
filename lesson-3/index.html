  1. MUST Look at your Random results. Which sort made the most comparisons? Which made the fewest?
  2. MUST Were you right about the winner of the race in Part 1? Explain what you saw.
  3. SHOULD When the list size doubles (1,000 → 2,000 → 4,000 → 8,000), roughly how many times bigger does the number of comparisons get for bubble sort? For insertion sort? For merge sort?
  4. SHOULD Use your doubling pattern to predict how many comparisons bubble sort would make for 16,000 items. Then explain why bubble sort is a bad choice for very large lists.
  5. SHOULD Look at your 4,000 Nearly sorted result. Which sort won? Explain why, using what each algorithm does.
  6. COULD Look at your 4,000 Reversed result. Why is a reversed list the worst case for bubble and insertion sort, but makes little difference to merge sort?
  7. COULD Merge sort won the random race. Give one reason a programmer might still choose insertion sort instead.
  8. COULD Why do we compare comparisons rather than milliseconds to decide which algorithm is better?

How it counts: bubble sort compares every neighbouring pair each pass and stops after a pass with no swaps (as in class). Insertion sort counts each comparison with the item to the left. Merge sort counts each comparison while merging.
